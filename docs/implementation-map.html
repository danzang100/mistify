A run, end to end

Eight stages, in order. Each one is a real sequence step: the output of the stage above is the only input to the stage below, and every stage records what it did in the scratchpad's own metrics table.

  1. Detect adapters/registry.py

    Each registered adapter scores a sample; the winner is the best-scoring adapter of the most specific tier above the confidence floor, not the highest score outright. Loki JSONL scores a perfect 1.0 as generic JSON, which is how specificity came to exist. Compression is sniffed by magic number, never by extension; binary is refused by name; a directory reads as one incident.

  2. Parse adapters/{json_lines,otlp,loki,raw_lines}.py

    Four formats, all streaming — peak memory is flat regardless of file size. Nothing unrecognised is refused: raw_lines reads one record per line, invents no timestamp beyond a line ordinal, and says so in the metrics so the report can distrust the incident window.

  3. Redact redaction/redactor.py

    Immediately after parse and before anything else — templater, database, or model — sees a record. Five entity types by default; the same source value always yields the same placeholder [IPV4:a7f2] within an incident, so the model can correlate on it without recovering it. Optional reversible vault, off by default, written to its own file because the model's SQL channel can read any table.

  4. Template templating/{drain_wrapper,calibration}.py

    Drain3, with the similarity threshold calibrated per file against a sample rather than guessed once. A file that does not compress gets a lower cluster ceiling — 2.15× throughput on a real CI log for 0.17% more fragmentation.

  5. Rank scratchpad/anomaly.py

    A deterministic score per template from severity, burstiness and rarity, computed from the incident's own distribution — no model, no baseline corpus. It decides the digest the investigation starts from and the signal set it is held to. This is where most of today's work went; see below.

  6. Investigate agent/loop.py

    A bounded model loop with five tools over the scratchpad. It cannot read the log file. Every tool call is logged before the model sees the result, and a citation naming an id the model was never shown is refused.

  7. Challenge agent/adversarial.py

    A different model — enforced at config load — attacks the conclusion, and the investigation rebuts. Objections carry ids so an answer lands on the objection it was written for. One check is model-free: was a high-scoring template left out?

  8. Report report/generator.py

    Markdown, HTML or PDF, rendered from the scratchpad rather than from the loop's narrative. Leads with health warnings — degraded parse, poor clustering, a budget-limited run, a ranking with no severity to rank by — then findings with their cited rows, then the challenge.

The scratchpad is the interface

One SQLite file per incident, and the only thing any downstream stage reads. The report renders from it, the scorer scores it, the model queries it through a read-only connection with an authorizer. Nothing scrapes the rendered document — a scraper fails silently when the document moves, and did, producing a table of confidently wrong numbers during development.

The ranking, and what was wrong with it

The score is a weighted sum — severity 0.5, burstiness 0.3, rarity 0.2, normalised — never a product, because the most frequent template in any incident has rarity exactly zero and a product would silence the loudest line in the file.

The digest is the top 40 templates, embedded in the system prompt. It is the model's entire first view of the incident. In September it was measured against ground truth for the first time, and the result was that none of it worked on CI logs: across all five LogDx-CI dev cases, zero ground-truth markers reached the top 40 — including a 170-template case where the top 40 is a quarter of the file.

Three terms, three degeneracies

Severity was guessed per line by a regex reading only upper-case log levels, so 97.1% of lines mapped to nothing and the heaviest term was correctly detected as uninformative and dropped. Burstiness is max_per_bucket ÷ (count ÷ total_buckets), so a template that fired once divided by a mean of 1/total_buckets and scored the maximum. Rarity cannot separate anything when 53–99% of templates in every case occur exactly once.

With all three flat, thousands of templates tied, and the tie-break was template_id — the order lines first appeared. The digest was the build's setup section, which is systematically the wrong end of a CI log.

What shipped measured

Severity is recovered from the template's own words when the source carries no severity field: ERROR-equivalent for failure vocabulary, WARN-equivalent for hedging vocabulary, INFO otherwise, on the same non-linear scale the severity field used, so no weight was retuned. ANSI is stripped first — a CI log paints its errors red and \x1b[31;1merror has no word boundary before error. It is still dropped when the recovered values are constant, which is the log-entirely-on-fire case. anomaly.severity_source records which of the three happened.

A single occurrence now scores zero burstiness. One event has no distribution to be concentrated in; the old value was an artefact of the denominator, and it is what fused 507 of one case's 9,307 templates into a single tied block.

The investigation loop

The model is given the ranked digest and five tools, and works until it writes a conclusion or runs out of tool calls. It cannot read the log file.

What bounds it

Twenty tool calls, then one final turn asking it to conclude from what it has; investigate.budget_limited is recorded so the report can say the investigation did not finish rather than presenting it as one that did. Tool output older than three steps is reduced to its header line, because the whole conversation is re-sent every step and one wide slice would otherwise be paid for forever. The system prompt — digest included — is built once and never edited, so a provider that caches prefixes can serve it from cache.

What pushes it new

A conclusion that ignores something the run was shown is sent back, up to pipeline.coverage_nudges times. Two questions, strongest first: a signal template that no note cites, and — added today — the three highest-ranked digest templates the run never pulled lines from. That second question exists because the first stopped being enough: measured across fifteen runs, the loop opens a median of 4 of the 40 templates it is handed, and every ground-truth marker it failed to cite sat in a template it never opened.

Two runs may not share one scratchpad. investigate now refuses an incident that already holds notes and asks for --resume (keep them, and say so in the opening turn) or --restart (delete the previous notes, queries and critique). Inheriting silently is how a run comes to be scored against findings it did not write.

Critique and report

The critique runs on a model that must differ from whichever model wrote the conclusion — enforced at config load, because a critique sharing a model with the thing it checks is the correlated-blind-spot problem the architecture exists to avoid. Objections carry stable ids the rebuttal quotes back. What was conceded, and the confidence after being challenged, are stored separately from the original.

In practice on the free tier it often does not run at all: gemini-3.5-flash allows 20 requests per day, and every critique in the five-case sweep of 4 September died on that cap. The run is still scored on what it completed, which is a deliberate harness property rather than an accident.

Memory is flat to the byte across a 3× file size for all four. At 10 GB, storage binds before CPU: ~15–25 GB of scratchpad.

The single largest win was not an optimisation but a bug: Drain3 was writing its entire cluster tree on every new cluster — 97.5% of a 489-second ingest, every write discarded by the next. Removing it took 4,000 lines from 130.31 s to 3.06 s. Parallel redaction gives 3.20× on its own stage and 1.55× end to end; Amdahl caps the whole run near 1.7× because redaction is 42% of an ingest, so eight workers reach 90% of the ceiling and sixteen buy 2% more.

One premise did not survive checking. Multi-line records were billed as the reason OpenSSH sits at 0.718 grouping accuracy. OpenSSH_2k.log has zero continuation lines — so do Hadoop, BGL and Apache. In CI logs the rate is 0–10%, and GitHub Actions prefixes every line with its own timestamp, so the usual "no timestamp means continuation" rule finds nothing. It is worth doing for pytest assertion blocks and rustc diagnostics, not as a cardinality fix.

Where Langfuse fits

Five seams, in the order they pay off. The project has one property that makes this unusually safe: everything a model ever sees has already been through redaction, so a trace carries [IPV4:a7f2] and never the address. The vault is the one thing that must never be exported.

  • llm/base.py — the LLMProvider protocol

    A tracing provider that wraps any other and emits one generation per converse(): model, latency, prompt and completion, and the Usage the seam already returns. One decorator class in llm/registry.py::build_provider covers the loop, the critique, the judge and the bootstrapper at once, because all four go through this seam.

    emits: generation · model, input/output/cached tokens, stop reason

  • agent/loop.py — one trace per investigation

    The loop already numbers its steps and logs every tool call before the model sees the result. Each step becomes a span, each tool call a child span carrying the query and row count from query_log. The incident id is the natural trace id, and investigate.* metrics — steps, nudges, compactions, input growth — are the trace's metadata.

    emits: trace · spans per step and tool call · tags for outcome, budget_limited

  • eval/harness.py — datasets and runs

    The strongest fit. LogDx-CI cases are a dataset; each sweep is a dataset run; each Check is a score, named exactly as it is today (cites[...], avoids[...]). The new Check.scorable flag maps cleanly onto not scoring a run rather than scoring it zero — which is the distinction the vacuity gate exists to preserve, and one a naive export would destroy.

    emits: dataset run · one score per check · run-level metrics

  • eval/judge.py — model-graded scores

    The entailment judge already returns a verdict plus a one-sentence reason per note. That is a Langfuse score with a comment, attached to the same trace as the run it judges, which is what makes "the citations resolved but the claim did not follow" visible next to the claim rather than in a separate report.

    emits: score · supported/unsupported + reason

  • agent/loop.py::SYSTEM_PROMPT — prompt management

    The system prompt is a module constant today, so a prompt change is a code change and two sweeps a week apart cannot be compared unless someone remembers. Langfuse's prompt registry would version it and let a run record which version produced it. Worth doing after the ranking work settles, since the same argument applies to the anomaly weights and those live in config already.

    emits: prompt version on every trace

How it should be wired

Opt-in, like --judge: a tracing: block in config.yaml with enabled: false by default, credentials from the environment beside GEMINI_API_KEY, and a no-op tracer when it is off so no code path branches on whether tracing exists. Two properties of this project should be preserved rather than traded away — mistify eval with no flags works offline, and the three model-free harnesses stay model-free. A tracer that reaches for the network by default breaks both.

Self-hosting is the better default here. The scratchpad and the traces contain the same redacted log text, and this project has consistently declined to send anything it can avoid sending. Langfuse runs from its own compose file; point the SDK at it with LANGFUSE_HOST.

Reproducing any of this

Nothing below calls a model except the last one.

uv run mistify ingest --source examples/incident.jsonl --incident-id demo
uv run mistify eval --digest --logdx dev
uv run mistify eval --baseline templated
uv run mistify eval-templating --sim-th 0.3 --sim-th 0.4 --sim-th 0.5
uv run mistify eval --logdx dev --runs 3 --no-adversarial

The corpora download on demand into .cache/ and are never committed. Budget roughly 120k tokens and 9–22 steps per real case, and space the requests at llm.min_interval_seconds: 5.5 — the shipped 4.0 is exactly the free tier's 15 requests per minute with no headroom.
